# Astra Reseller Bot

Локальный бот для магазина FunPay: AI-ключи, аренда Steam, SMM, сообщения и журнал. Windows, macOS и Linux. Для работы компьютер должен оставаться включённым и подключённым к интернету.

## Сначала получите кабинет

1. Напишите владельцу: **[@neva_glamur67](https://t.me/neva_glamur67)**. Он вручную создаст аккаунт и передаст логин и пароль. Открытой регистрации нет; скачивание бота само по себе не даёт доступа.
2. Войдите в [кабинет реселлера](https://api.gserver.online/seller) → **API разработчика → Создать ключ**. Сохраните `sk-dev-…`: он показывается один раз. Ключ покупателя `sk-ag-…` здесь не подходит.
3. Установите [FunPay Lite Bot из Chrome Web Store](https://chromewebstore.google.com/detail/funpay-lite-bot/amicfiagmpbgfiiopieeemlkblfeeeip). Войдите в свой FunPay, откройте в расширении **Golden Key / API access** и скопируйте golden_key.
4. Вставляйте golden_key только в локальный установщик. Он даёт доступ к аккаунту FunPay: не отправляйте его владельцу, покупателям или в GitHub Issues.
5. Выключите в других ботах и расширениях автоответы, автовыдачу и автоподнятие, которыми будет управлять наш бот, чтобы действия не дублировались.

## Установка

Скачайте `funpay-bot-reseller.zip` из [последнего релиза](https://github.com/BlackWh1te/astra-reseller-bot/releases/latest) и полностью распакуйте. Готовому релизу не нужен `npm install`.

### Windows 10/11

Откройте **start.cmd** двойным щелчком. Если Windows заблокировала архив, откройте свойства архива, нажмите «Разблокировать» и распакуйте заново. Установщик найдёт Node.js 22+ или загрузит его с nodejs.org с проверкой SHA-256, задаст вопросы и настроит фоновый запуск от вашего пользователя.

Команды из установленной папки: `start.cmd status`, `start.cmd logs`, `start.cmd restart`, `start.cmd stop`, `start.cmd setup`.

### macOS — Intel и Apple Silicon

Откройте Терминал. Введите `bash `, перетащите **start.sh** в окно и нажмите Enter. Либо из распакованной папки:

```bash
bash ./start.sh
```

Установщик найдёт или установит Node.js 22 с проверкой SHA-256. Бот устанавливается в `~/FunPayBot` и запускается LaunchAgent при входе. Mac должен оставаться включённым; закрытая крышка на батарее может остановить работу.

Команды: `bash ~/FunPayBot/start.sh status`, `logs`, `restart`, `stop`, `setup`.

### Linux

Установите Node.js 22 LTS и npm официальным пакетным менеджером своей ОС. От обычного пользователя:

```bash
bash ./start-linux.sh
```

Фоновая служба использует `systemd --user`. Команды: `bash ~/FunPayBot/start-linux.sh status`, `logs`, `restart`, `stop`, `setup`. Для работы после выхода из SSH администратор сервера может включить linger. Без systemd используйте `node bot.mjs run` в своём менеджере процессов.

## Первая проверка

Установщик запросит golden_key, ключ `sk-dev-…`, название магазина, настройки ИИ и тестовый/боевой режим. Начните с тестового режима: сообщения покупателям не отправляются, ключи не создаются. Проверьте соединение, бюджеты, цены и предпросмотр лотов, затем включите боевой режим через повторную настройку.

Панель: **http://127.0.0.1:4777** на компьютере с ботом. Она слушает только loopback, не сеть. Остановка бота останавливает и локальную панель; кабинет на сайте продолжает работать независимо.

## Ключи, единицы и активность

В локальной панели и в кабинете можно вручную создать ключ из своего пула, выбрать доллары или токены, пополнить ключ, включить/выключить, скопировать секрет и удалить с возвратом неиспользованного остатка. Токеновые объёмы задаются в миллионах или миллиардах. История сохраняется; выполняющийся запрос может временно препятствовать удалению.

Журнал активности показывает только свои ключи: покупателя или имя ключа, модель, время, входящие/исходящие токены, статус и длительность. Тексты запросов, ответы и ключи доступа не показываются. Если бот или компьютер недоступен, ручное управление остаётся в кабинете `/seller`.

## Балансы и пополнение

API имеет отдельные токеновый и долларовый пулы. Steam и SMM имеют собственные долларовые балансы. Токены, доллары, деньги Steam и SMM не конвертируются и не оплачивают друг друга автоматически.

В **Баланс и пополнения** выберите направление и объём. Откроется Telegram с логином кабинета и заявкой. Владелец подтвердит цену и реквизиты, проверит оплату и зачислит средства вручную. Кнопка не списывает деньги и не пополняет пул. До настройки оптового прайса показывается «цена по запросу».

Доступ к моделям, Steam и SMM выдаёт владелец. Пустой баланс, отсутствие товара или отключённый доступ не обходятся изменением локального кода.

## Обновления и свои тексты

**Обновления → Проверить обновления → Установить**. До установки проверяются подпись Ed25519, версия, срок манифеста и SHA-256 каждого файла. Сторонние адреса, повреждённые файлы и старые версии не принимаются. При выполняющемся заказе установка откладывается. После установки служба перезапускает бот, и панель возвращается.

`data/config.json`, `data/state.json` и журнал не заменяются. Свои `knowledge.md` и `lot-templates.json` сохраняются; стандартные обновления кладутся рядом как `.new`. Старые программные файлы сохраняются в `backups/update-…`.

Шаблоны названий, описаний и сообщений находятся в `lot-templates.json`. Команда `node bot.mjs templates` показывает текущие тексты. Маркер лота нужен для сопоставления; изменения применяются к будущим публикациям, не переименовывая старые лоты.

## Безопасность и поддержка

Ключи поставщиков и административные секреты не входят в клиент. API разработчика ограничен вашим кабинетом. Сервер проверяет владение ключами и заказами и наличие бюджета. Клиент не является доверенным источником для зачисления средств: владелец проверяет реальные платежи.

Подпись защищает обновления доверенного приложения при сохранности ключа издателя. Первая установка требует доверия к источнику; вредоносные программы под вашей учётной записью могут читать доступные ей локальные файлы. Не публикуйте `data/`, `backups/`, ключи и пароли. При ошибке передайте владельцу версию, ОС, время, действие и обезличенную ошибку — без полного файла настроек.

## Разработчикам

Текущая логика восстановлена из установленной версии 1.3.1 в читаемый `app/engine.mjs`, без встроенных библиотек и зависимости от серверного репозитория. Безопасность, интерфейс, ручное управление и обновления — отдельные модули `app/`. Зависимости зафиксированы в lock-файле.

```bash
npm ci
npm test
npm run build
```

Для подписи нужен закрытый ключ, соответствующий `app/update-key.mjs`. Он не входит в Git или релизы. Workflow использует GitHub Secret `RELEASE_SIGNING_KEY` и тег `v<version>`.
